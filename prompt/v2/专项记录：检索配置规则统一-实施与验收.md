# 检索配置规则统一：实施与验收记录

> 文档性质：跨专题配置规则的协作决策与实施追溯，**不是**“优化十六：检索重排升级为精排”的正式功能提示词或效果结论。
> 日期：2026-09-23；开发分支：`feature/retrieve-config-rules`；基线：`8b1c259`。

## 决策背景

优化十六实施前发现检索参数存在多层来源。经讨论，先独立统一请求、Profile、环境配置和代码默认值的关系；本次不接入 Qwen3 精排，也不改三档 Profile 的返回数量或套餐分级。

## 已确认的生效规则

1. 套餐权限和资源配额是硬约束；先检查所选 Profile 是否允许，再依据**最终生效**的检索选项校验 hybrid、rerank、query rewrite 等功能。不允许时拒绝请求，不静默降档。
2. 不传 Profile 的正式 HTTP API 默认使用 `balanced`；`speed`、`balanced`、`quality` 的预设字段优先于请求中同名字段。预设**未定义**的字段仍可由请求提供。请求即使会被覆盖，也先经过 API Schema 类型与范围校验。
3. `custom` 对每个字段采用“显式请求值 > 实际环境配置 > 代码默认值”。显式 `false` 与省略字段含义不同。前端和 curl 的请求没有优先级区别。
4. `RERANK_ENABLED` 和 `QUERY_REWRITE_ENABLED` 是未指定时的默认值，不是全局熔断开关；套餐权限仍然有效。API Key、模型、Provider、超时等服务端专属配置不由检索请求选择。
5. `custom` 的 hybrid 检索中，只传 `top_k` 不再同时改变两路召回数量。未传 `vector_top_k` / `bm25_top_k` 时，分别使用 `HYBRID_VECTOR_TOP_K` / `HYBRID_BM25_TOP_K`。
6. `query_options.enabled` 显式传入时优先于 `strategy`；冲突组合 `true + noop` 执行改写，`false + rewrite` 不执行改写。未传 `enabled` 时才使用 `strategy` 或服务端默认值。
7. 调试台 `custom` 取消勾选精排或改写，发送 `enabled:false`；勾选则发送 `true`。curl 可省略这些字段使用服务端默认值。

### 真实业务链路

使用加载本分支代码的临时 FastAPI 实例（`127.0.0.1:18080`）、已有租户和知识库，通过 HTTP 完成以下验证；没有修改知识库或文档。

| 场景 | 验证结果 |
| --- | --- |
| `custom` 显式关闭精排与改写，环境默认均为开启 | 两项最终均为关闭；返回 3 条，hybrid 两路召回默认分别为 20 |
| `custom` 仅显式传 `vector_top_k=4` | 向量侧为 4，BM25 侧沿用环境值 20 |
| `balanced` / `speed` 与显式同名参数冲突 | 生效值取预设，未用显式参数绕过套餐功能校验 |
| 不传 Profile | 使用 `balanced` 预设 |
| 显式 `enabled=false` 且 `strategy=rewrite` | 不执行改写 |
| 显式 `enabled=true` 且 `strategy=noop` | 实际执行改写且未降级 |
| `quality` 显式关闭精排、改写 | 按预设执行两项，未降级，返回 5 条 |
| 多知识库 `balanced` 检索 | 实际检索成功，metadata 标记多知识库 |
| 被预设覆盖的非法参数 `top_k=0` | 仍由请求 Schema 拒绝 |
| free 套餐 `speed` 携带不允许的显式功能参数 | 预设仍生效，检索成功，未开启禁用功能 |
| free 套餐 `balanced`、`custom`、不传 Profile | 均返回权限错误 `20013` |

真实浏览器调试台也验证了 `custom` 勾选后取消精排、改写时的最终请求体：两项均发送 `enabled:false`；页面展示检索结果，浏览器没有报错。
