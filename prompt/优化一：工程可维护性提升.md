## 增加日志

我需要为**项目**做**体系化、生产级、可直接落地**的日志改造，核心要求：可用、高效、简洁

### 核心日志需求

1. **统一日志格式**：包含时间、日志级别、模块名、函数名、行号、请求 ID（可选）、日志内容
2. **必须覆盖的场景**

   - 接口请求 / 响应日志：URL、方法、请求体、响应体、耗时、状态码
   - 大模型交互日志：prompt、LLM 返回结果、调用耗时、模型名称、异常信息
   - 系统报错日志（单独日志文件，不要和正常日志放到一起）：完整堆栈、异常类型、上下文信息
   - 业务关键节点日志
3. **日志输出**：控制台彩色输出 + 文件按大小 / 时间滚动（防止日志文件过大）
4. **性能要求**：异步安全、低侵入、不阻塞业务
5. **代码规范**：结构化、可复用、带配置项、支持全局调用

请直接输出：

1. 可直接运行的**日志工具类**（logging + RotatingFileHandler）
2. **接口请求日志装饰器**
3. **大模型交互专用日志函数**
4. **全局异常捕获日志**
5. 最佳实践使用示例

## 错误码规范

为**项目生成统一、可维护、前后端通用**的**错误码 + 错误信息相关内容**，要求简洁、高效

### 核心要求

1. **统一错误结构**

   - code：数字 / 字符串错误码
   - msg：用户友好提示
2. **错误码分类规则**

   1. 0：成功

   - 20000\~29999：接口 / HTTP / 请求相关
   - 30000\~39999：数据库 / 存储
   - 40000\~49999：**大模型 LLM 专属**（限流、超时、无返回、内容违规、token 超限）
   - 50000\~59999：系统 / 服务异常
3. **错误信息规则**

   - 对外提示：简洁、安全、不泄露技术细节
   - 对内日志：完整、带上下文、方便排查
4. **必须包含**

   - 错误码枚举类
   - 统一异常类
   - 快速抛错工具函数
   - 全局异常捕获返回标准结构
   - 错误码要足够细化
5. 使用示例

```Python

   
    SUCCESS = (0, "成功")
    PARAM_ERROR = (10001, "参数错误")
    UNAUTHORIZED = (10002, "未授权，请登录")
    FORBIDDEN = (10003, "权限不足")
    NOT_FOUND = (10004, "资源不存在")
    METHOD_ERROR = (10005, "请求方法错误")

    # 接口/HTTP 20000~29999
    API_REQUEST_ERROR = (20001, "接口请求失败")
    API_TIMEOUT = (20002, "接口请求超时")
    API_RATE_LIMIT = (20003, "接口调用超限")

    # 数据库 30000~39999
    DB_ERROR = (30001, "数据库操作失败")
    DATA_DUPLICATE = (30002, "数据已存在")

    # LLM 大模型专用 40000~49999
    LLM_ERROR = (40000, "大模型调用失败")
    LLM_TIMEOUT = (40001, "大模型响应超时")
    LLM_NO_RESPONSE = (40002, "大模型未返回有效内容")
    LLM_CONTENT_VIOLATION = (40003, "内容违规，大模型拒绝生成")
    LLM_TOKEN_LIMIT = (40004, "上下文长度超限")
    LLM_RATE_LIMIT = (40005, "大模型调用频率超限")
    LLM_MODEL_ERROR = (40006, "模型不存在或未部署")

    # 系统错误 50000~59999
    SERVER_ERROR = (50000, "服务器异常")
    SYSTEM_BUSY = (50001, "系统繁忙，请稍后再试")
```
